# coordinating-agents 1.3.0

Coordinates coding agents under any multi-agent orchestrator through its current help, verification of the effective model, effort and permission mode, and following states, questions and restarts. An accepted send does not prove receipt or result; permissions and reserved effects need a written answer from the person and a check afterwards. Reference files for Herdr, Orca, teamctl and Dorothy map each one onto the same cycle.

Version 1.3.0 brings the Herdr reference to herdr-core: `hc` runs and reads the agents, the Herdr app shows them, and the traps measured on macOS (halving splits, the split pane's folder, children that end with their parent, refused sends to a blocked program) are named. The older `herdr` multiplexer keeps its own section with every earlier rule. Layouts must end even: rows of equal height and panes of equal width inside each row, built by cut order when splits only halve, and measured before any agent starts. The coordinator reads the remaining quota when a usage tool exists. A command such as the `master` skill may make its invocation the written answer to named effects for one run; every other reserved effect still needs the person. The Orca reference adds macOS 1.4.245, and the agent-type notes add Claude Code 2.1.317, Codex 0.166.0 and Antigravity CLI 1.4.12. Every 1.2.0 rule stays.

Acquire the whole `skills/orchestration/coordinating-agents/` directory, including `references/`, from `Tacuchi/agent-skills` once the ref `skill/coordinating-agents/v1.3.0` exists; it works with no other harness and no other offer.
